# Security Policy

This repository primarily contains educational content and publishing tools, but reports may still involve unsafe example code, dependency risks, malicious build behavior, exposed private data, or links that could harm readers.

## Report privately

Do not open a public issue for:

- an exposed credential or personal secret;
- a build script that can execute unexpected commands;
- a malicious dependency or downloadable artifact;
- a vulnerability that could affect contributors running the toolchain; or
- a private-data or attribution issue requiring confidential evidence.

Use GitHub private vulnerability reporting when it is enabled. If it is unavailable, contact the repository owner through the public profile at https://github.com/vinayreddykalluri and request a private reporting channel. Do not include exploit details or secrets in the first public message.

## Include

- affected file and revision;
- impact and realistic attack path;
- minimal reproduction that does not expose third-party data;
- suggested mitigation, if known; and
- whether the issue has been disclosed elsewhere.

## Scope boundary

Interview examples are educational and are not production security guarantees. Reports that improve secure defaults, validation, resource limits, or warnings are welcome. General Java or dependency vulnerabilities should also be reported to their upstream maintainers.
